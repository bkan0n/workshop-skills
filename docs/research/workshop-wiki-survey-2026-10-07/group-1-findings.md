## Mandatory foundation candidates

A small shared foundation should teach the following failure-preventing rules, then link to detailed references. These candidates add substantial content beyond Wait without turning the foundation into an action catalog.

1. **Events have execution context and triggering semantics.** Ongoing rules trigger when all conditions become true, not every tick while true; a false condition is required to rearm. An unconditional Global rule starts at server start; an unconditional Each Player rule starts as each player loads. Event Player means the event's subject, which is the attacker for Dealt Damage and victim for Took Damage; healing uses Healer/Healee. [4824](https://workshop.codes/wiki/articles/4824), [4825](https://workshop.codes/wiki/articles/4825), [4820](https://workshop.codes/wiki/articles/4820), [4819](https://workshop.codes/wiki/articles/4819), [7450](https://workshop.codes/wiki/articles/7450), [4813](https://workshop.codes/wiki/articles/4813).
2. **Waiting, looping and call modes are different.** Loop restarts the entire action list and needs an executed Wait. While/For use a matching End; For's stop bound is exclusive, and For Player Variable uses only the first supplied player. Wait quantizes to documented 16 ms intervals, whereas Wait Until can finish in zero ticks and ignores rule conditions. Call Subroutine pauses the caller; Start Rule runs concurrently, with an already-running policy scoped to the same player/global entity. Both inherit event context; subroutines cannot have conditions. [4389](https://workshop.codes/wiki/articles/4389), [4383](https://workshop.codes/wiki/articles/4383), [4384](https://workshop.codes/wiki/articles/4384), [4480](https://workshop.codes/wiki/articles/4480), [9298](https://workshop.codes/wiki/articles/9298), [6041](https://workshop.codes/wiki/articles/6041), [4455](https://workshop.codes/wiki/articles/4455), [1292](https://workshop.codes/wiki/articles/1292).
3. **Know which inputs are sampled versus live.** Reevaluation is input-specific. Camera position/look-at and throttle-transform inputs always reevaluate; forcing-position reevaluation never changes which Player was selected. Chase requires the variable to already have the destination's number/vector type. Stopping a chase retains its current value. [7648](https://workshop.codes/wiki/articles/7648), [4457](https://workshop.codes/wiki/articles/4457), [4449](https://workshop.codes/wiki/articles/4449), [6027](https://workshop.codes/wiki/articles/6027), [4336](https://workshop.codes/wiki/articles/4336), [4464](https://workshop.codes/wiki/articles/4464).
4. **Persistent actions need ownership, handles and cleanup.** Effects/icons/texts, modifiers, assists, DoT/HoT, held buttons and forced movement are ongoing state. Store the appropriate Last… ID when later targeted destruction/stopping is needed; capacity exhaustion often makes creation fail. By Player Left Match the departed player's variables and other information are unavailable, so cleanup cannot depend on reading them then. The global HUD-handle example illustrates the ownership idea, but its fixed-delay ordering needs redesign before becoming a canonical pattern. [4342](https://workshop.codes/wiki/articles/4342), [4343](https://workshop.codes/wiki/articles/4343), [4445](https://workshop.codes/wiki/articles/4445), [4454](https://workshop.codes/wiki/articles/4454), [4821](https://workshop.codes/wiki/articles/4821), [4827](https://workshop.codes/wiki/articles/4827).
5. **Scope and coercion matter.** Most player-array setters affect every supplied player, but not every API does: For Player Variable uses the first. Indexed Set Variable replaces a non-array with an empty array and extends beyond the end with zeros; indexed Modify also zero-extends. Percent-based setters generally refer to raw/normal values, while scaling uses multipliers, and clip/weapon/room indexes differ. [4384](https://workshop.codes/wiki/articles/4384), [4415](https://workshop.codes/wiki/articles/4415), [4429](https://workshop.codes/wiki/articles/4429), [4394](https://workshop.codes/wiki/articles/4394), [4422](https://workshop.codes/wiki/articles/4422), [9662](https://workshop.codes/wiki/articles/9662), [4482](https://workshop.codes/wiki/articles/4482), [4484](https://workshop.codes/wiki/articles/4484), [4450](https://workshop.codes/wiki/articles/4450).
6. **Engine operations are not interchangeable.** Set Player Health changes no damage/heal credit or stats and affects only living players; Heal does not resurrect; Respawn can move living players to spawn; Resurrect uses death position. Damage modifiers differ from Set Damage Dealt because they exclude barriers/turrets, and a zero modifier can prevent Kill. [4518](https://workshop.codes/wiki/articles/4518), [4386](https://workshop.codes/wiki/articles/4386), [7550](https://workshop.codes/wiki/articles/7550), [7549](https://workshop.codes/wiki/articles/7549), [4445](https://workshop.codes/wiki/articles/4445), [4942](https://workshop.codes/wiki/articles/4942).
7. **Read failures as a combination of context, limits and game-mode compatibility.** A no-op may be a full slot, unsupported bot operation, incompatible game mode, absent weapon, no selected hero, or exhausted persistent resource—not faulty syntax. Keep a compact diagnostic checklist pointing to the relevant domain reference. See examples below.

The foundation should not assert the deeper active-rule retrigger/filter-abort semantics solely from the short event entries: those entries omit them. Group 3's tutorial findings may supply that missing layer, with their own uncertainty labels.

## Selective references suggested by the evidence

### Execution, variables, reevaluation and native syntax

Keep an execution/context matrix: event subject; usable contextual values; rising-edge versus discrete event; synchronous versus concurrent subroutine; Wait versus Wait Until; whole-list Loop versus structured loops. Rule-condition-list actions (Abort/Loop If Condition Is True/False) test all/any rule conditions, unlike action-local predicates. Native C-style syntax maps assignments and expressions to long-form Workshop actions/values; **`^` means exponentiation**. Its table's OR row uses display glyphs unsuitable for copying. [4324](https://workshop.codes/wiki/articles/4324), [4325](https://workshop.codes/wiki/articles/4325), [4391](https://workshop.codes/wiki/articles/4391), [4392](https://workshop.codes/wiki/articles/4392), [4852](https://workshop.codes/wiki/articles/4852).

Use a per-action input-lifetime table rather than a blanket rule that reevaluation means everything updates. Health-pool maximum only reevaluates when both Recoverable and Reevaluation are true; nonrecoverable pools shrink/disappear as damaged. Decimal literals in Set Ultimate Charge reportedly round unless wrapped in a function such as Absolute Value/First Of. [6164](https://workshop.codes/wiki/articles/6164), [4439](https://workshop.codes/wiki/articles/4439).

### Lifecycle, HUD/effects, visibility and sound

Different handles serve text versus entities versus health pools/modifiers/assists. Destroy Effect additionally accepts an array of entity IDs (March 2026 source, not tested here). Play Effect is transient and exempt from the Create Effect capacity, but its article's “as many as you want” must not become a claim of unlimited performance. Big/Small Message lasts a fixed four seconds; Small Message spam is reported to disconnect viewing players. [8473](https://workshop.codes/wiki/articles/8473), [9268](https://workshop.codes/wiki/articles/9268), [6037](https://workshop.codes/wiki/articles/6037), [9529](https://workshop.codes/wiki/articles/9529).

Player-valued Position is not always equivalent to Position Of(player): visual entities may follow or sit above the player; explosion sounds can sound different or be silent with a player value. Explosion sound color reportedly affects friendly/enemy variants, despite generic Create Effect text saying color does not apply to sounds. Record this as a specific exception/conflict requiring context. [4340](https://workshop.codes/wiki/articles/4340), [6071](https://workshop.codes/wiki/articles/6071), [4345](https://workshop.codes/wiki/articles/4345), [2765](https://workshop.codes/wiki/articles/2765), [4342](https://workshop.codes/wiki/articles/4342).

Nameplates/outlines distinguish viewed and viewing players. Outline refresh is reported to be delayed and dependent on self/ally/enemy, life state, melee distance, sight and FOV changes. Spectator-host input can be read through Host Player, while other spectator input uses Local Player only in visual-element fields; spectator controls map to unexpected Workshop buttons. This belongs in an advanced client-context/UI reference, not a generic server input recipe. [4501](https://workshop.codes/wiki/articles/4501), [8803](https://workshop.codes/wiki/articles/8803), [4830](https://workshop.codes/wiki/articles/4830).

### Movement, camera, collision and physics

Impulse, acceleration, facing, throttle and forced position are separate mechanisms. Unit directions normalize internally; acceleration may fight gravity/friction; throttle transforms scale input before rotating it. Attach permits multiple children per parent, prevents free child movement, and teleport detaches. Disabling environment collision excludes floors by default. Large scaled players interacting with complex geometry can severely increase server load. [4327](https://workshop.codes/wiki/articles/4327), [6022](https://workshop.codes/wiki/articles/6022), [4457](https://workshop.codes/wiki/articles/4457), [6165](https://workshop.codes/wiki/articles/6165), [4509](https://workshop.codes/wiki/articles/4509), [9662](https://workshop.codes/wiki/articles/9662).

Acceleration's archived stopping-threshold formula `Max Speed^2 - Rate/62.5` is surprising/dimensionally unclear. Preserve the exact claim with uncertainty, and prioritize a reproducible test before using it to derive movement code. The horizontal walking-speed cap also needs hero/version context. [6022](https://workshop.codes/wiki/articles/6022).

### Combat, attribution and projectiles

Projectile owner never receives its own projectile effect even when included by affected team. Null start/direction uses eye/facing. Amount Scalar changes meaning depending on explosion radius: critical multiplier at zero radius versus damage at explosion edge when positive. Oversize's maximum differs by type; negative gravity arcs upwards; homing strength 1 reportedly never loses target. Effects-only projectiles and damaging/healing projectiles must be distinguished. The action pages omit projectile owner-leave behavior reported by Group 3. [5175](https://workshop.codes/wiki/articles/5175), [4545](https://workshop.codes/wiki/articles/4545), [4546](https://workshop.codes/wiki/articles/4546).

Environment kill credit expires on landing; Set Status assist credit differs from the persistent Start Assist relationship, which distinguishes defensive/offensive assists by allegiance. Keep damage/heal modifier, status and attribution behavior together. [4523](https://workshop.codes/wiki/articles/4523), [4436](https://workshop.codes/wiki/articles/4436), [4524](https://workshop.codes/wiki/articles/4524).

### Bots, heroes and spawning

Dummy bots require Workshop-driven actions, valid available slots and mode-compatible team values. Move Player To Team/Remove Player do not support them; naming should wait until spawn. Communicate reportedly stopped working on bots, with no patch or subtype details. Preload Hero is capacity-limited and replaces a previous preload for that player; repeatedly issuing it does not accumulate heroes, and earlier array entries are prioritized. [4341](https://workshop.codes/wiki/articles/4341), [4540](https://workshop.codes/wiki/articles/4540), [4541](https://workshop.codes/wiki/articles/4541), [4542](https://workshop.codes/wiki/articles/4542), [6032](https://workshop.codes/wiki/articles/6032), [4401](https://workshop.codes/wiki/articles/4401).

Changing allowed heroes can force selection/respawn, while forcing a hero may respawn in place; stopping the force does not itself respawn. Empty allowed-hero input has no effect, which creates an edge case for the tutorial “remove current hero then reset availability” workaround when only one hero was allowed. Changing respawn time on an already dead player affects their next death. [4426](https://workshop.codes/wiki/articles/4426), [4448](https://workshop.codes/wiki/articles/4448), [4469](https://workshop.codes/wiki/articles/4469), [4856](https://workshop.codes/wiki/articles/4856), [4433](https://workshop.codes/wiki/articles/4433).

### Match flow, configuration and release workflow

Pause Match Time does not pause player/objective/game-mode advancement and does not bypass documented session lifetime. Slow Motion affects the whole simulation and supports only up to 100%. Completion/scoring/respawning can be decoupled from the base mode. Victory/draw/score actions have FFA/control/elimination/team-mode restrictions; Restart Match requires 30 seconds of existing match time. [4399](https://workshop.codes/wiki/articles/4399), [4435](https://workshop.codes/wiki/articles/4435), [4364](https://workshop.codes/wiki/articles/4364), [4366](https://workshop.codes/wiki/articles/4366), [4367](https://workshop.codes/wiki/articles/4367), [4347](https://workshop.codes/wiki/articles/4347), [4348](https://workshop.codes/wiki/articles/4348), [4349](https://workshop.codes/wiki/articles/4349), [4350](https://workshop.codes/wiki/articles/4350), [4539](https://workshop.codes/wiki/articles/4539).

Workshop Settings materializes its menu from used values; names are unique; category grouping is case-sensitive and script-ordered; settings sort by number then alphanumerically; Combo returns a zero-based index. Sharing snapshots all lobby settings excluding players/bots/AI; new code and overwrite-existing-code are distinct operations. [2168](https://workshop.codes/wiki/articles/2168), [1724](https://workshop.codes/wiki/articles/1724), [2042](https://workshop.codes/wiki/articles/2042).

### Budgets and data catalogs

Maintain generated dated catalogs for resource limits/extension costs, stock-argument element counts, projectile radii, payload checkpoint samples, sound/effect names and asset references. Preserve unit and measurement metadata: projectile size is **radius**, checkpoint samples depend on payload speed, stock-action counts are not a universal fixed cost, recordings do not reveal true looping duration, and effect screenshots omit animation. [1862](https://workshop.codes/wiki/articles/1862), [2112](https://workshop.codes/wiki/articles/2112), [8242](https://workshop.codes/wiki/articles/8242), [1714](https://workshop.codes/wiki/articles/1714), [4838](https://workshop.codes/wiki/articles/4838), [4840](https://workshop.codes/wiki/articles/4840).

Document performance mechanisms separately from static limits: Inspector recording particularly affects array modification; player collision scaling is expensive; large static vector/string sets can be encoded to save elements but require a decoder with runtime work. The compression example is educational, not a validated robust serialization library: it lacks delimiter escaping/malformed-data handling and uses shared global parser state. [4370](https://workshop.codes/wiki/articles/4370), [4381](https://workshop.codes/wiki/articles/4381), [9662](https://workshop.codes/wiki/articles/9662), [5932](https://workshop.codes/wiki/articles/5932).

## Editorial conflicts, gaps and exclusions

- **Do not promote copied snippets to canonical templates.** If/Big Message examples omit End; If compares Host Player with True; Damage's Mercy loop has no stopping condition despite claiming to stop when healing ends; a Damage example supplies a damager array although documented type is a single player. Keep extracted API facts while independently testing rewritten examples. [6067](https://workshop.codes/wiki/articles/6067), [6037](https://workshop.codes/wiki/articles/6037), [7025](https://workshop.codes/wiki/articles/7025).
- **Retain source-specific uncertainty.** Generic sound/color wording conflicts with the explosion-sound guide; ability-scaling “impossibility” conflicts with scaling certain abilities; the ultimate-voice-cancel table is an uninspected remote image; the acceleration formula needs validation; bot communication, outlines and Small Message spam are specific regression/quirk claims without reproduction details. [2765](https://workshop.codes/wiki/articles/2765), [5900](https://workshop.codes/wiki/articles/5900), [9662](https://workshop.codes/wiki/articles/9662), [8176](https://workshop.codes/wiki/articles/8176), [6022](https://workshop.codes/wiki/articles/6022), [6032](https://workshop.codes/wiki/articles/6032), [8803](https://workshop.codes/wiki/articles/8803), [9529](https://workshop.codes/wiki/articles/9529).
- **API metadata is not uniformly clean.** Duplicated Last Created Entity Entity, incorrect movement-collision descriptions in audio/health entries, wrong knockback parameter label, incomplete Count OF snippets, voice-pitch default outside its documented range, likely old/new voice-action aliases, and malformed OR display glyphs require normalized catalogs with preserved provenance. Ledger records each affected article.
- **Different language/tool boundaries need explicit labels.** OSTW pathmaps are an external ecosystem and fit a deferred pathfinding companion roadmap, not OverPy syntax. Workshop.codes @if/@for/@each are compile-time editor directives, not native Workshop and not OverPy. Inline HTML is purely site authoring and can be excluded from runtime skills. [4859](https://workshop.codes/wiki/articles/4859), [2082](https://workshop.codes/wiki/articles/2082), [1768](https://workshop.codes/wiki/articles/1768).
- **Game verification remains a separate status.** Agreement among archive articles strengthens internal consistency but does not verify current game behavior. Limits (128/256 effects, 64 modifiers, 16 health pools per type, 128 subroutines, 12 hero+skin preloads), hero measurements, patch regressions and UI/share workflows especially need dated labels. Record practical test ideas alongside disputed claims rather than blocking the initial portable skill.

## Suggested design impact

Keep the native Workshop skill as owner of the common runtime foundation plus domain references. The evidence supports references for execution/context, state and lifecycle, effects/HUD/audio/client context, movement/physics, combat/projectiles, bots/heroes/spawning, mode/configuration/release workflow, and budgets/performance. This is more useful than dividing solely by Actions versus Values versus Events. Generated catalogs should preserve complete API/data coverage, while curated prose captures interactions, defaults, no-ops and failure modes.

OverPy should link to these runtime topics while owning its own language/compiler/decompiler/project workflow. None of the site directives or OSTW syntax should silently enter the OverPy skill. Complex examples (pathfinding, compression, boss/ultimate customization) should become optional deeper recipes or roadmap entries after the core behavior is established and example validation is available.
